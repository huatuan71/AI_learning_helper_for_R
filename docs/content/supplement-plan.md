# R语言AI助教知识库补充清单与编写框架

适用范围：`K01`—`K43`，共43个知识点、8个课程单元。  
用途：把不同知识点分派给其他线程编写，之后由一个整合线程统一审核并导入知识库。  
当前版本：1.1.0。

## 一、补充目标

现有知识点已经包含来源、解释、函数语法、参数说明、运行示例、实际输出、易错提醒和练习提示。本轮不重复改写这些基础字段，主要补充以下教学内容：

- 从“知道是什么”推进到“能看懂、能模仿、能独立完成、能发现错误”。
- 每个知识点至少增加2个分层例题、1个完整练习和1种适合的图解。
- 所有代码、输出和图形均可追溯、可复现、可核验。
- 不把预先计算的结果说成网页实时执行结果。
- 不为了凑数量添加与课程无关的知识。

## 二、协作与文件规则

为避免多个线程同时修改 `course.json` 产生冲突，内容线程只提交草稿，不直接编辑正式数据文件。

建议每个知识点使用独立文件：

```text
content/supplements/
├─ K01.md
├─ K02.md
└─ ...

ai_tutor/content_assets/
├─ code/K01_example_01.R
├─ data/K01_example_01.csv
└─ images/K01_visual_01.svg
```

协作要求：

1. 每个线程只负责分配给自己的知识编号。
2. 草稿文件名必须使用知识编号，例如 `K06.md`。
3. 图、数据和代码文件名必须以知识编号开头。
4. 内容线程不修改接口、前端、`course.json` 和其他线程的草稿。
5. 整合线程最后统一检查、运行代码、生成图片并导入正式知识库。
6. 如果资料与当前知识库矛盾，只记录“待核对”，不要自行覆盖原内容。

## 三、每个知识点的统一交付标准

### 3.1 必填内容

每个知识点必须补齐以下内容：

- `学习目标`：2—3条，使用“能够……”描述。
- `先备检查`：1—2个用于判断是否具备前置知识的小问题。
- `直观理解`：80—150字，避免只重复函数定义。
- `为什么`：至少2条，解释行为背后的原因。
- `基础例题`：1题，代码控制在12行以内。
- `应用例题`：1题，使用成绩、问卷、实验或业务小数据。
- `逐步讲解`：解释关键语句及数据如何变化。
- `预期输出`：与代码逐字对应，并标明验证环境。
- `图解方案`：说明图要表达什么，而不是只写“配一张图”。
- `易错案例`：至少1个错误写法、错误表现、原因和参考修正。
- `练习题`：题目、输入数据、预期任务、解题提示、参考答案、参考输出。
- `自测题`：2题，其中至少1题要求预测代码结果。
- `追问建议`：例题、易错点、练习、相关知识各1条。
- `来源与验证`：资料来源、R版本、包版本、运行状态和核验人。

### 3.2 选填内容

- 适用场景与不适用场景。
- 另一种写法及其差异。
- 与相邻知识点的对比表。
- 小型数据文件。
- SVG/PNG图解及替代文本。
- 单元综合任务中的使用位置。

### 3.3 内容长度建议

| 内容 | 建议范围 |
|---|---:|
| 直观理解 | 80—150字 |
| 每个例题代码 | 5—20行 |
| 每个例题讲解 | 3—6步 |
| 自测题 | 2—3题 |
| 单张图说明 | 50—100字 |
| 单个知识点草稿 | 800—1500字，不含代码和输出 |

## 六、图解与数据规范

### 6.1 图解选择原则

- 图必须帮助理解数据结构、执行顺序、边界或结果，不能只作装饰。
- 优先使用SVG，统计图可使用R输出的PNG。
- 每张图必须同时提供标题、说明和替代文本。
- 图中文字在手机宽度下仍应可读，避免把整段解释写进图片。
- 颜色不是唯一信息通道，还应使用标签、线型或形状区分。
- 不使用来源不明的网络图片。

### 6.2 示例数据原则

- 优先使用10—30行的小型原创教学数据或R自带数据集。
- 数据必须包含清楚的字段说明和单位。
- 如果加入缺失值、重复键或异常值，要明确这是教学设计。
- 不使用真实个人信息，不使用无法核实的业务数据。
- 同一例题的数据、代码、输出和图必须一致。

### 6.3 推荐复用数据

为降低43个知识点之间的认知负担，可复用以下小数据主题：

- 学生成绩：类型、缺失、筛选、排序、分组、函数和循环。
- 实验测量：矩阵、数组、缺失、异常值和批量处理。
- 问卷等级：因子、字符串、分组与数据框。
- 商品或电影模拟数据：字符串、日期、连接和综合清洗。
- R自带数据：`iris`、`mtcars`、`airquality`，使用前说明字段含义。
