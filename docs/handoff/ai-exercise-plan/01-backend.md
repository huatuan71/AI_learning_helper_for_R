# 对话一提示词

复制下方内容给后端执行对话，并附上集成对话提供的工作树绝对路径与共同基线提交号。

---

请实现R语言AI助教的“大模型出题”后端。先阅读适用AGENTS.md和 `docs/handoff/ai-exercise-plan/00-coordination.md`。项目位于 `ai_tutor/`，使用 `codex/ai-exercise-api` 的独立工作树和共同基线。

先检查已交付的AI总结及现有模型会话、适配器、取消、错误响应和课程数据实现。交付以下内容。

1. 新增 `POST /api/learning/exercises`，按共同契约接收1至3个知识点、1至5题、难度和题型，返回包含提示、参考答案和真实课程出处的完整题目批次。
2. 新增专用Pydantic模型和出题服务。复用现有厂商适配器、CallBudget、会话并发、run_for_session和统一错误处理，使用 learning-exercise-v1 提示词。
3. 服务端从真实知识库及错误案例构建有界上下文，制定本批题型和知识点分布。题目覆盖请求范围，单选题有4个唯一选项及有效参考索引，代码题有必要背景和目标。
4. 校验数量、类型、难度、知识范围、重复题、引用、JSON与长度。后端生成题目ID和批次ID、填充实际课程出处及not_executed标记。题目和参考答案的AI生成属性始终清楚。
5. 普通生成关闭搜索工具，输出预算遵守用户设置且上限8192。配置失效、取消、断开、超时和无效输出使用可复用错误语义。日志与响应遵守现有脱敏和no-store约定。

主要新增 `app/ai/exercise_schemas.py`、`app/ai/exercise_generation.py`、`app/api/learning_exercises.py`，并在 `app/main.py` 注册路由。

通过MockTransport测试三厂商、搜索关闭、参数边界、知识覆盖、参考索引、重复和无效输出、恶意课程文本、用量、取消及配置变化。准备供浏览器集成复用的题目假数据。结构验证通过和人工题目质量审阅分别报告。

完成后提交本分支，交付提交号、OpenAPI契约、请求响应样例、测试结果、输出校验范围、前端需要处理的实际错误码，以及供集成对话使用的假数据和接入位置。
