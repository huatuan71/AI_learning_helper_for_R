# R代码语法高亮实施规划

编写日期为2026年11月17日。项目位于仓库根目录 `ai_tutor/`。本轮交付目标为所有明确的R代码展示和专用R代码输入区提供一致的语法着色。

## 交互与配色

采用按语法角色分色的方案。相同类别在各页面使用相同语义颜色，浅色页面与知识地图深色详情分别使用适配色值。代码块沿用现有玻璃材质，通过颜色、缩进和留白体现代码结构。

| 类别 | 视觉方向 | 示例 |
|---|---|---|
| 关键字与特殊值 | 紫色 | if、else、for、function、TRUE、FALSE、NA、NULL |
| 函数调用 | 蓝色 | mean()、is.na()、data.frame() |
| 字符串 | 绿色 | "score"、'分类' |
| 数字 | 棕金色 | 10、0.5、1e-3、2L |
| 注释 | 灰绿色 | # 检查缺失值 |
| 运算符 | 蓝灰色 | <-、<<-、|>、%>%、$、:: |
| 普通标识符与标点 | 高对比度正文色 | x、score、括号和逗号 |

最终色值由界面集成对话根据实际玻璃底色确定，并记录可读性检查结果。代码字体使用项目等宽字体与中文后备字体。普通代码正文保持可读字号，文本对比度按WCAG AA检查，颜色之外保留原始文字和结构。

语法色表示代码的词法类别。现有错误提醒、代码未运行验证和模型生成标识继续使用各自的文字与提示样式。题目中的错误位置可使用下划线或独立背景层表达。

## 覆盖范围

- 首页的R代码预览、纠错对照和明确的R行内片段。
- AI问答的流式代码、最终回答、旧记录、提交代码和参考修正。
- 知识地图详情、课程示例与学习小结中的典型代码。
- 课程复习题、变式题、参考答案中明确的R代码区域。
- 代码纠错与问答“添加代码”的专用R输入框，以及本地.R文件读取后的编辑区。
- AI出题模块若已集成，覆盖题目代码、参考代码和专用代码作答输入区。尚未集成时，将统一组件与接入清单交给出题集成对话。

渲染入口明确声明语言。R和r使用同一语法规则，运行输出按输出文本展示。其他语言的代码根据其实际语言标记处理，未知语言采用安全文本展示。混合自然语言的问答、报错与简答输入保持各自的文本编辑语义。

## 技术方案

推荐本地固定版本的Prism核心及R语法，采用manual模式并按组件显式调用tokenize构建安全DOM。Prism提供返回字符串和token序列的底层接口，适合保留原代码文本。依赖保存版本、来源、许可证和可复现构建说明。执行对话下载前核对当前官方包内容及实际版本。[Prism接口文档](https://prismjs.com/docs/prism)

官方R语法文件已有注释、字符串、布尔值、数字、关键字、百分号运算符等规则。项目适配层补充函数调用、反引号名称、原始字符串和现代管道等实际用例，并测试规则优先级。高亮属于词法展示，能力边界在交接中明确。[官方R语法源文件](https://github.com/PrismJS/prism/blob/master/components/prism-r.js)

原生textarea用于纯文本编辑。输入区采用原生textarea与高亮展示层叠加的方案，实际textarea保留原ID、value、焦点和编辑行为。高亮层只负责视觉并设置aria-hidden，读取和提交仍使用textarea值。[textarea官方说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/textarea)

## 共享组件契约

对话一新增 `static/r-highlighter.js`，提供以下接口。

```javascript
tokenizeR(source)
// 返回按原顺序拼接可还原source的 {type, text} 数组。
// type使用固定白名单，包含plain、keyword、function、string、number、comment、operator、punctuation。

rCodeFragment(source)
// 返回DocumentFragment，使用文本节点和受控span构造。
// fragment.textContent与source一致。
```

底层解析失败或超出实际测试的性能阈值时，组件返回完整原始文本，交接中说明触发条件。源码中包含HTML、R比较符、script字样和特殊Unicode字符时，作为代码文本显示。词法分类只映射受控类名。

对话二新增 `static/r-code-editor.js`，提供以下接口。

```javascript
enhanceRTextarea(textarea, {renderCode})
// renderCode由集成方传入rCodeFragment，可先以纯文本渲染回调独立开发。
// 返回 {refresh, setValue, destroy}。
// setValue(source, {emitInput:false})用于显式赋值并更新视觉层。
```

textarea是唯一编辑数据源。refresh()只读取value并更新高亮层，setValue()遵循已有程序填充语义，destroy()取消监听、观察器和未完成绘制并恢复原生显示。对话一、二的实际实现合入后，编辑器使用真实R高亮组件完成最终测试。

对话三为codeBlock()增加可选language参数并兼容现有调用。Markdown调用显式传递解析到的语言，结构化R课程字段显式声明R。代码复制从源字符串读取，保持原有标题和按钮行为。明确的R行内片段使用同一语法规则。

## 输入区要求

- 高亮层和textarea的字体、字号、行高、内边距、tab-size、换行及滚动完全对齐。
- 专用代码编辑区默认保持代码行结构，长行在组件内部横向滚动，页面宽度保持稳定。
- 保留光标、选择、撤销重做、剪切粘贴、拖放、触摸选择、原生Tab焦点和当前字数检查。
- compositionstart至compositionend期间保护中文输入法，必要时使用原生文字显示，提交组合输入后恢复高亮。
- 对所有程序赋值路径显式同步。MutationObserver只用于可观察的属性及DOM变化，value属性赋值另行处理。
- 隐藏和展开代码区、只读或禁用状态、视口变化和手机键盘出现后均保持对齐。
- 高对比度模式、组件失败或浏览器兼容问题时恢复可用的原生文本编辑显示。

## 数据与性能

高亮DOM只用于显示。复制、请求、草稿、记录保存和导出均使用原始代码数据。对Markdown已解析出的代码字符串建立渲染前后等价断言，记录原有换行归一化方式。覆盖空格、Tab、空行、末尾换行、CRLF和中文注释。

RFileInput的100KB文件校验和现有10000字符提交限制沿用实际接口约束。长文件、长回答、未闭合字符串及流式半截代码进行性能测量。流式更新按代码节点做有界合并调度，输入时更新视觉层不打断实际文字输入。阈值依据测试确定并记录设备与耗时。

样式集中于 `static/r-code-theme.css`，使用固定前缀的类名及CSS变量，包含浅色、知识详情深色、选择和高对比度适配。PWA白名单包含新增模块、依赖和样式，资源版本由对话三统一更新。

## 最终验收

1. 函数、字符串、注释、数字、关键字、特殊值、赋值、命名空间、成员访问和管道显示预期类别。
2. 覆盖反引号函数名、原始字符串、转义引号、中文、未闭合代码、恶意HTML及超长行。
3. 全部展示入口、流式和最终回答、旧记录、复制及导出使用同一语法和原始文本。
4. 输入、撤销重做、粘贴、文件替换、清空、示例填充、记录回填和草稿恢复通过正常入口测试。
5. 原生textarea的值与实际API提交一致，收起代码区后保持现有提交行为。
6. 知识详情深色、其他页面浅色、磨砂背景、错误提示和未运行标签在高亮后可读。
7. 桌面1440px和390×844检查布局及内部滚动，验证键盘、触摸和无障碍文本不重复。
8. 输入法组合事件自动测试与实际人工输入分开记录，Android、iOS、macOS和Windows按实际验证范围报告。
9. 执行实际收集的pytest、适当的浏览器、文件、流式、存储、总结和PWA回归，修复问题后重测受影响范围。
10. 交付组件方法、版本及许可证、接入清单、截图、测试结果、性能参数、已知限制和最终集成提交号。
