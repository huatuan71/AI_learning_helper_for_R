# AI学习总结实施规划

编写日期为2026年11月17日。适用项目位于仓库根目录 `ai_tutor/`。本文中的新接口、总结数据和界面为待实现契约。

## 产品行为

在“学习记录 → 小结”增加“AI总结”按钮，沿用今日、最近7天和自选日期范围。用户主动生成，界面显示生成状态并支持取消。再次生成需要主动操作。

总结包含近期重点、学习记录中反复出现的困难、复习优先项和下一步建议。每条观察或建议附带知识点或学习记录入口。现有本地统计和课程小结继续提供日期、次数、作答等事实。

模型只能根据提交的证据作出观察。现有复习评级属于用户自评，使用提示、查看参考答案和独立作答分别表述。没有独立测评证据时使用“需验证”“建议检测”等表述。掌握等级与复习时间继续由现有调度规则计算。

使用模型设置中当前选择的厂商、模型和后端会话密钥。生成按钮附近说明本期统计和对话摘录将发送至所选厂商，并按厂商计费，提供“发送内容”折叠预览。网页搜索模式下，总结使用该模型的普通生成能力。

联网生成成功的总结保存在当前设备。离线时可以查看已保存总结和现有本地小结。模型未配置时提供“配置模型”，网络错误允许重试，旧总结在失败后仍可查看。

第一版交付手动生成、取消、保存、查看、复制、文本导出和来源跳转。后续再评估定时生成、跨周期趋势和由模型生成复习题。

## 核对过的现有实现

- `static/learning-center.js` 的 `renderSummary()` 按所选日期筛选事件、作答和对话，渲染课程要点、易错提醒及下一步模板。
- `static/learning-store.js` 使用 IndexedDB，数据库版本和完整档案格式当前均为1。个人数据包含 conversations、events、cards、attempts、bookmarks 和 settings，课程快照独立保存。
- 学习档案支持完整导出、合并导入、重复去重、事务写入和跨标签页通知。问答工作区只显示最近100条，完整历史在 IndexedDB。
- `static/model-settings.js` 管理现有模型设置。密钥由后端会话保存，模型配置有空闲过期和重启失效机制。
- `app/ai/providers.py` 提供 `ADAPTERS`、`CallBudget` 和 `Provider.complete()`。`app/ai/sessions.py` 管理会话及并发，`app/ai/service.py` 的 `run_for_session()` 处理断开和配置变化。
- `static/api-client.js` 提供同源 JSON 与 SSE 请求。公共弹出提示已支持快捷操作，模型设置弹窗和提示采用磨砂玻璃。

## 拟新增接口

采用 `POST /api/learning/summary`，首版使用一次 JSON 响应。界面显示“生成中”和取消入口，成功校验后展示总结。

请求包含以下字段，详细 Pydantic 模型由对话一实现并导出 OpenAPI，对话二、三按本契约接入。

| 字段 | 约定 |
|---|---|
| `schema_version` | 固定为1，表示总结输入契约版本 |
| `input_fingerprint` | 前端归一化输入的SHA-256，用于缓存和竞态关联 |
| `period` | `start_date`、`end_date` 使用 YYYY-MM-DD，`time_zone` 为有效IANA时区 |
| `metrics` | `topic_count`、`study_event_count`、`attempt_count`、`independent_self_rated_count`、`conversation_count`，由本地代码按范围计算 |
| `coverage` | `total_evidence_count`、`included_evidence_count`、`truncated`、`policy_version`，说明摘录覆盖范围 |
| `evidence` | 最多50条，稳定编号、原始记录ID、类型、时间、知识ID、摘录及作答信号 |

每条 evidence 包含 `id`、`source_id`、`kind`、`at`、`knowledge_ids`、`text`。kind 使用 `conversation`、`attempt` 或 `event`。作答可附 `signals`，仅包含 `grade`、`hint_used`、`answer_revealed` 和 `question_type`，由实现明确类型与空值规则。原始ID用于回到对应记录，证据ID用于模型输出引用。

单条摘录最多1200字符，请求总量最多120 KiB UTF-8，最多43个真实知识ID。对话的提问、回答和报错摘录合计计入单条上限。完整代码、个人备注与密钥不进入首版摘录。前后端都验证数量、长度、日期及字段，前端预览与实际提交使用同一个输入对象。

metrics 表示当前浏览器所保存的统计，后端校验类型和合理关系。模型输出的统计文字不能替代页面中的代码计算结果。

成功响应包含 `request_id`、`status: "ok"`、`mode: "ai"`、`provider`、`model`、`prompt_version`、`input_fingerprint`、`generated_at`、`period`、`coverage`、`usage`、`duration_ms` 和 `summary`。

summary 的结构如下。

```json
{
  "overview": "本期学习情况的简短概述",
  "topics": [
    {"knowledge_id": "K06", "observation": "记录支持的观察", "evidence_ids": ["c:example"]}
  ],
  "review_priorities": [
    {"knowledge_id": "K06", "reason": "建议复习的依据", "evidence_ids": ["c:example"]}
  ],
  "next_actions": [
    {"knowledge_id": "K06", "action": "完成一次独立练习", "reason": "对应学习依据", "evidence_ids": ["c:example"]}
  ],
  "uncertainties": ["本期记录缺少独立作答，掌握程度仍需检测。"]
}
```

各数组数量和文本长度设明确上限。知识ID必须来自实际课程及本次允许范围，证据ID必须存在于本次输入。overview 和 uncertainties 可说明整体情况，具体知识观察、复习优先项和行动建议要附证据。模型输出校验失败时返回统一错误结构。

无学习数据时返回 `status: "no_data"`、`mode: "local"` 和 `summary: null`，在发起模型调用前结束处理。模型未配置或会话失效沿用现有配置错误反馈。其他状态码和错误码在实现、测试后由对话三写入正式接口说明。

首版提示词版本使用 `learning-summary-v1`。记录、作答和模型已有回答作为待分析数据传入，系统提示词要求遵循事实及证据，缺少证据时说明局限。调用使用普通生成并关闭搜索工具。输出Token预算遵守用户设置且上限为4096，沿用现有有界请求预算。

## 本地数据与缓存

对话二将 IndexedDB 升级至版本2，增加 `summaries` 存储。完整档案升级至 schemaVersion 2，支持导入旧的 schemaVersion 1，旧档案的 summaries 按空数组处理。

保存的总结含稳定ID、完整有效响应、输入指纹、证据定位元数据、厂商、模型、提示词版本和生成时间。摘要摘录只在生成请求中使用，缓存仅保留结果及定位元数据。缓存键包含日期范围、时区、指纹、厂商、模型和提示词版本。指纹基于归一化输入，排除生成时间、对象键顺序和临时UI状态。

总结ID由缓存键稳定生成，同一输入的重新生成以有效新结果原子更新。档案合并遇到相同ID时优先保留较晚生成的有效结果，时间相同则按归一化内容确定顺序。总结数量设为最多100条，按生成时间保留最近结果，并继续遵守现有完整档案20 MiB上限。

相同输入默认复用已保存结果，新增记录、评级变化、模型切换或提示词升级后标明总结对应旧数据。“重新生成”由用户主动触发。生成中切换范围或快速点击时，结果按其原始范围保存，当前页面只展示与当前范围相符的结果。

清空对话时，同一事务删除引用被清除对话的总结。重置个人档案清除全部总结。完整档案导出、导入和跨设备去重包含 summaries，导入内容继续按本地不可信输入校验。历史总结的原始证据可能缺失，提供可理解标记并禁用失效跳转。

- 日期边界、时区、无数据、仅浏览记录、仅对话、提示后作答、自评和重复数据都得到正确处理。

- 错误知识ID、伪造证据、超长输出、无效JSON和提示词注入样本受到校验。
- 旧数据库升级、旧档案导入、完整新档案恢复、重复导入、事务失败及双标签页行为通过测试。

- 在1440px和390×844检查生成、取消、来源跳转、复制与导出，验证磨砂样式、键盘和安全文本。
- 执行实际收集的 pytest、现有算法和适当的浏览器、PWA集成检查。测试记录写实际结果和设备范围。
