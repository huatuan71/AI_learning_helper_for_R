# 线程一提示词

将下面的提示词完整复制到一个独立聊天。

```text
请实现R语言AI助教的跨平台本地学习存储与自动复习算法，完成代码、测试和本线程交接说明。

仓库路径示例为 E:/projects/r-ai-tutor，项目位于 ai_tutor。
你的专属分支为 codex/learning-core。

先读取适用的AGENTS.md，以及 docs/handoff/learning-plan/00-coordination.md。它规定了本轮共享的数据结构、模块接口、算法规则、文件归属和交接要求。按该约定实现，保证其他线程能够直接调用。

请使用独立工作树。优先使用当前聊天已分配的工作树。若当前处于主工作区，由你为本分支创建专属工作树，建议位置为本仓库的 .worktrees/learning-core，并将 /.worktrees/ 加入本机 .git/info/exclude。检查当前分支和已有改动后再操作。

你的修改范围
- 新增 static/learning-store.js。
- 新增 static/review-scheduler.js。
- 新增 tests/learning_core_test.mjs。
- 新增 docs/learning-core.md。

先检查现有 static/app.js 的 safeRecord、旧记录读写、send、清空和导出逻辑，以及 data/course.json 的结构。当前旧记录键为 r-tutor-mock-v1，最多恢复最近100条。

一、存储

使用浏览器原生IndexedDB，导出协作约定中的 learningStore 单例。
保存对话、学习事件、复习卡片、作答记录、收藏、设置和课程快照。数据库带schema版本和升级逻辑。
完整学习档案独立于对话列表的显示数量保存。

采用现有字段白名单保存和迁移对话。档案导出涵盖学习数据与设置。导入时校验app标识、schema版本、大小、数组数量、字段类型、知识编号、时间和文本长度。

以事件ID、作答ID和稳定对话ID实现去重。旧记录重复导入、网络重试、刷新与多标签页并发需要保持一致。导入先校验再事务写入，合并事件后按确定顺序重算卡片，保证相同输入事件集合得到相同结果。

保存一次作答时，将作答记录和卡片更新放在同一个事务中。事务提交成功后才通知调用方。处理存储不可用、配额不足、升级阻塞和连接失效，错误消息应便于新手理解。

采用BroadcastChannel或等效方式通知其他同源标签页刷新。只清空对话和重置整个学习档案分别对应协作约定的方法。

二、复习算法

导出 createCard、scheduleReview、buildReviewQueue 三个纯函数。所有可调参数集中定义，测试可以传入now。

严格落实协作约定的六级间隔、四种评分、提示和看答案后的评级上限、同日重试、跨日提升、每日次数限制、最多两道首次检测题、错题优先和直接先修补强。

浏览、查看答案、请求练习和代码纠错分别记录行为证据，复习评级使用有效作答。成功讲解绑定主要知识点，引用中的附带知识保留为来源信息。

普通讲解后安排次日检测。主动加入复习进入当前任务。跳过任务仍可继续处理。重复提交同一个作答ID返回已保存结果。

处理时区边界、输入时间错误、连续失败、最高和最低等级、同一题重复刷、缺失知识点、循环先修关系与大量逾期任务。排序提供确定的同分规则。

三、测试与交付

使用项目已有Node环境运行纯算法测试，选择与浏览器一致的ES模块方式。为事务、迁移、导入和多标签页安排真实浏览器测试步骤，明确哪些已经运行，哪些等待集成。

至少验证新卡、24小时首次检测、各评级排程、提示后降级、同日限制、跨日升级、重复作答、队列配额、稳定排序、先修去重和循环保护。

将模块接口、数据表、算法版本、可调参数、升级方法、测试命令和结果写入 docs/learning-core.md。

完成后检查差异，只提交你的归属文件。提交信息使用 feat: add local learning storage and review scheduler。最终返回提交编号、实际测试结果，以及界面线程需要注意的具体接入事项。
```
