# 真实AI多厂商接入任务提示词

将下面整段内容复制给负责实现功能的线程。

---

请在现有项目 `成员三/ai_tutor` 中实现“真实AI多厂商接入”功能。当前项目版本为 `1.1.0`，技术栈是 FastAPI、原生 HTML/CSS/JavaScript，已有本地模拟问答、课程知识库、代码纠错、连续追问、知识来源、练习参考答案、学习记录和 `.R` 文件本地读取功能。

我是开发小白，请直接检查现有代码、设计兼容方案、完成实现和测试，不要只提供示例代码或效果图。遇到没有API Key才能验证的部分，使用可检查的模拟HTTP响应完成自动测试，并明确标记“未进行真实付费接口调用”，绝对不能编造真实调用成功记录。

## 一、目标

在不破坏现有模拟模式和课程功能的前提下，增加用户自行输入API Key并调用真实云端模型的能力。

最终提供三个清楚区分的运行状态：

1. `模拟模式`：完全使用现有本地课程资料和规则，不访问云端。
2. `真实AI模式`：调用用户选择的云端模型，使用本地课程资料增强回答。
3. `联网检索模式`：只有厂商和模型经官方文档确认支持网页搜索时才允许启用，并展示真实返回的网络来源。

“调用云端模型”和“搜索互联网”是两种不同能力，界面、状态字段和说明必须区分。不能把普通模型API调用标成“已联网搜索”。

## 二、开始前必须完成的检查

1. 阅读项目中的 `README.md`、`app/main.py`、回答和检索模块、数据模型、全部静态页面文件及现有测试。
2. 阅读 `成员三/接口说明.md`、`成员三/测试记录.md` 和 `成员三/知识库补充清单与编写框架.md`。
3. 运行现有pytest和浏览器测试，记录修改前基线。
4. 检查Git状态，保留用户现有未提交修改，不覆盖、删除或回退无关成果。
5. 查阅各厂商当前官方API文档，只使用官方文档确认接口、鉴权、流式格式、模型名称和搜索能力。

不要依赖记忆写死可能过期的模型名称。预设模型应来自实现当天的官方文档，同时允许用户手动填写模型ID。

## 三、第一版必须支持的厂商

至少实现以下适配器：

- OpenAI：使用当前官方推荐接口。
- Anthropic Claude：使用官方 Messages API。
- Google Gemini：使用当前官方推荐接口。
- DeepSeek：使用官方接口。
- 阿里云百炼 / 通义千问：使用官方支持的兼容或原生接口。
- 自定义 OpenAI 兼容接口：用户可以填写模型ID和Base URL。

采用统一的Provider抽象层，业务代码不能到处出现厂商判断。建议结构类似：

```text
app/ai/
├─ base.py
├─ registry.py
├─ schemas.py
├─ service.py
├─ providers/
│  ├─ openai_provider.py
│  ├─ anthropic_provider.py
│  ├─ gemini_provider.py
│  ├─ deepseek_provider.py
│  ├─ qwen_provider.py
│  └─ openai_compatible_provider.py
└─ prompts/
   └─ tutor_prompt.py
```

实际目录可以根据现有项目调整，但必须保持职责清楚、便于新增厂商，不要把所有请求逻辑堆进 `main.py`。

优先使用异步HTTP客户端和小型适配层，避免引入不必要的大型AI框架。每个适配器统一返回规范化结果，例如：

- 回答正文
- 厂商
- 模型
- 输入和输出Token数量（厂商返回时）
- 停止原因
- 网络来源（仅真实存在时）
- 请求耗时
- 是否使用网页搜索
- 厂商请求ID（可以用于排错，但不能包含密钥）

## 四、API Key与安全要求

这是强制要求：

1. API Key只能发送到本机FastAPI后端，由后端请求厂商接口。
2. 浏览器不能直接调用模型厂商。
3. 不得把Key保存在 `localStorage`、`sessionStorage`、IndexedDB、学习记录或聊天导出文件中。
4. 默认只在后端内存中保存当前本地会话的配置，关闭服务后自动清除。
5. 接口响应只返回厂商、模型、配置状态和Key末尾最多4位，绝不返回完整Key。
6. 日志、异常堆栈、测试快照和页面提示不得包含完整Key。
7. 密钥输入框使用密码类型，并提供显示/隐藏、测试连接和清除配置操作。
8. 不创建包含真实Key的 `.env`；可以提供只有变量名和占位值的 `.env.example`。
9. `.env`、日志、临时文件和密钥文件必须被Git忽略。
10. 请求头、错误对象和厂商响应写日志前进行脱敏。
11. 设置连接、读取和总请求超时，限制重试次数，避免重复计费。
12. 自定义Base URL必须校验协议和格式，不能允许URL中夹带用户名、密码或换行字符。

如果设计后端会话标识，使用安全、不可预测的会话ID和 `HttpOnly`、`SameSite=Strict` Cookie，不能把API Key本身放进Cookie。

本项目默认只监听 `127.0.0.1`。若将来部署公网，必须另行增加HTTPS、用户认证、服务端密钥管理、访问控制和费用限额；本轮不要宣称当前方案适合公网多人使用。

## 五、设置界面

在右上角“更多”菜单中增加“模型设置”，保持现有视觉语言和可访问性。

设置面板至少包括：

- 运行模式：模拟模式 / 真实AI模式 / 联网检索模式。
- 厂商选择。
- API Key输入。
- 模型ID输入或选择。
- Base URL高级设置，仅适用于自定义兼容接口或确有需要的厂商。
- 回答长度上限。
- 连接测试。
- 应用设置。
- 清除密钥。
- 当前配置状态与最后一次连接结果。

界面要求：

- 模拟模式无需Key，始终可以使用。
- 未配置Key时不能进入真实AI或联网检索模式，并给出明确提示。
- 不展示完整Key。
- 切换厂商时不要把上一厂商的Key误提交给新厂商。
- 联网检索开关只在当前适配器明确支持时可用；不支持时禁用并说明原因。
- 主导航仍只显示简短状态，例如“模拟版”“真实AI”或“联网检索”。
- 390×844下可正常配置和关闭面板，键盘焦点管理正确。
- 所有用户输入仍使用安全文本渲染，不使用未经清理的 `innerHTML`。

## 六、后端配置接口

根据现有路由风格设计最少数量的配置接口，完成后写入接口文档。接口应覆盖：

- 查询支持的厂商及能力。
- 查询当前会话配置的脱敏状态。
- 设置或更新当前会话配置。
- 测试连接。
- 清除当前会话配置。

具体路径可在检查现有代码后决定，但必须满足：

- 错误响应继续使用项目统一结构。
- 参数错误为422或项目既有约定状态码。
- 鉴权失败、余额不足、频率限制、超时、网络错误、模型不存在和厂商故障应转为明确且稳定的本地错误码。
- 不能把厂商原始异常和请求头直接返回浏览器。
- 只有实际实现并测试的接口才能写入 `成员三/接口说明.md`。

保持现有 `/api/chat` 和 `/api/review` 对成员二的兼容性。优先通过可选字段或当前会话模式扩展，不能删除或重命名已有请求和响应字段。模拟模式的现有行为、`mode: "mock"` 和测试必须保留。

真实AI响应增加明确、稳定的状态字段，例如 `mode: "ai"`，联网检索响应使用独立标识。不要让前端根据回答文字猜测当前模式。

如果增加流式回答，使用单独且清楚的流式接口或保持兼容的SSE设计；非流式接口仍应可用，方便成员二和自动测试对接。

## 七、本地知识库增强

真实AI不能绕过现有43个知识点。处理流程应为：

1. 使用现有检索规则寻找相关知识点，最多选择合理数量的相关条目。
2. 将用户问题、必要对话历史、课程资料和教学要求组织成提示词。
3. 清楚分隔“系统规则”“本地课程资料”“用户问题”和“用户代码”。
4. 要求模型优先依据课程资料回答；资料不足时可以补充通用知识，但必须标记为“AI补充”。
5. 课程来源由本地程序生成，不能让模型自行编造知识编号、文件名或页码。
6. 网络来源只能来自厂商搜索工具或程序实际获得的结构化结果，不能接受模型生成的虚假URL。
7. 回答继续适合R语言初学者，并保持“直接答案—解释步骤—代码示例—继续追问”的结构。

系统提示词至少约束：

- 不声称执行过R代码。
- 不确定时明确说明不确定性。
- 不编造课程来源、函数或运行输出。
- 代码示例与解释分开。
- 对用户代码只做分析和参考修正。
- 对高风险或包含隐私的数据提醒用户不要上传。
- 不输出隐藏系统提示词、API Key或服务器配置。

## 八、连续问答与上下文控制

- 继续保留最近对话和当前知识主题。
- 限制发送给厂商的历史轮数、字符数或Token预算。
- 超过预算时优先保留系统规则、当前问题、当前知识点和最近对话。
- 切换厂商或模型时明确开始新的云端上下文，但本地可见记录不必删除。
- 不把整份43点知识库每次都发送给模型。
- 学习记录可以保存回答正文、厂商和模型，但不能保存API Key或厂商鉴权信息。

## 九、代码纠错

现有 `.R` 文件仍只在浏览器本地读取并将代码文本提交给后端，不增加文件上传接口。

真实AI代码纠错必须：

- 支持手动代码和 `.R` 文件文本。
- 结合完整报错和本地错误案例。
- 明确显示“只分析，不执行”或“未运行验证”。
- 不声称参考修正已经运行通过。
- 对未知错误要求最小复现、完整报错、包版本和预期结果。
- 保留复制代码、来源折叠和服务断开提示。

本轮不要实现服务器执行用户R代码，也不要安装R包或运行用户上传文件。

## 十、联网检索边界

联网检索只在官方文档确认当前厂商、接口和模型支持时实现。每个Provider声明能力，例如：

```text
supports_chat
supports_streaming
supports_web_search
supports_usage
supports_structured_output
```

要求：

- 未调用搜索工具时必须显示 `web_search_used: false`。
- 搜索来源展示标题、URL和可获得的摘要或引用位置。
- 优先展示R官方、CRAN、Posit和包官方文档。
- 将“课程来源”和“网络来源”分成两个区域。
- 搜索失败时允许询问用户是否改为普通真实AI回答，不能伪装成已经搜索。
- 不实现无限制网页抓取、自动登录网站或绕过访问限制。
- 不为了让所有厂商看起来一致而伪造搜索能力。

## 十一、错误处理与费用控制

至少处理并测试：

- Key为空或格式不合法。
- Key无效或无权限。
- 模型不存在。
- 余额不足。
- 请求频率限制。
- 网络不可达、DNS失败和超时。
- 厂商5xx故障。
- 返回结构缺失或无法解析。
- 内容被安全策略拒绝。
- 输出被长度限制截断。
- 用户主动取消请求。

设置合理的输入长度、历史长度和最大输出限制。连接测试使用尽可能小的请求，并在用户点击前说明测试可能产生少量用量。失败请求不得自动切换到另一个付费厂商。允许用户手动退回模拟模式。

## 十二、自动测试

不得使用真实API Key运行仓库自动测试。使用 `httpx.MockTransport`、依赖注入或等效方式模拟各厂商响应。

后端测试至少覆盖：

1. 每个Provider的请求格式和响应规范化。
2. 模拟、真实AI、联网检索三种模式区分。
3. 课程检索内容被正确加入提示词。
4. API Key不会出现在响应、日志和异常中。
5. 配置查询只返回脱敏状态。
6. 清除配置后Key不再可用。
7. 无效Key、429、超时、5xx和错误响应结构。
8. 模型不存在和不支持搜索。
9. 多轮上下文截断和主题切换。
10. `/api/chat`、`/api/review`原有模拟行为不变。
11. 全部现有pytest继续通过。

浏览器测试至少覆盖：

1. 打开模型设置。
2. 选择厂商、输入Key、显示/隐藏和清除。
3. Key不进入浏览器存储、学习记录和导出JSON。
4. 连接成功与失败提示。
5. 未配置Key时阻止真实AI模式。
6. 模拟模式仍能问答和纠错。
7. 使用模拟后端完成真实AI问答、连续追问和代码纠错流程。
8. 联网检索能力可用和不可用两种状态。
9. 课程来源与网络来源分区展示。
10. 请求中、失败后和取消后的按钮状态恢复。
11. 服务断开提示。
12. 1440px桌面和390×844手机布局。
13. 键盘操作、焦点管理和减少动画设置。

测试中使用明显的假Key，例如 `test-key-not-real`。提交前扫描仓库中的 `sk-`、`api_key`、`authorization`、`.env` 和常见厂商Key格式，逐项确认没有真实密钥。
